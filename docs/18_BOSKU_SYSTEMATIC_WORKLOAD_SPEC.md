# Bosku Systematic Workload Specification

## Purpose
Move deterministic administrative workload from the capster's memory and repeated manual work into the product.

## Active Layer
PROGRAMMATIC → SYSTEMATIC

Automation and Agentic are explicitly deferred unless later evidence proves Systematic insufficient.

## Primary Workloads
1. Customer lookup and history
2. Booking visibility
3. Visit/service recording
4. Price/service lookup
5. Daily operational totals
6. Daily report preparation
7. Photo/documentation tracking
8. Opening readiness checklist
9. Basic stock/readiness tracking
10. Clear service/payment/receipt state

## User Contract
The operator should mainly:
- prepare the shop
- serve customers
- cut hair
- clean
- maintain customer relationships
- review/confirm administrative results

The system should remember, search, calculate, organize, and present.

## Non-Goals
- Replace Kasir Pro
- Autonomous WhatsApp sending
- Autonomous social posting
- Complex inventory
- Predictive AI
- Agentic workflow
- Unofficial Kasir Pro bypass/integration

## Core Principle
If a deterministic table, state machine, calculation, checklist, or search solves the burden, do not introduce AI.
